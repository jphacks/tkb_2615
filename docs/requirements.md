# 製品要件と想定用途

## 目的

ShelterSimは、避難所運営に関する条件を検討するための実験用シミュレーターです。施設、Zone、通路、避難者、職員、物資、予定イベントを型付きデータで表現します。Scenarioを確認して実行し、記録を調べ、介入Branchと元のBranchを比較できます。

主な用途は探索的な計画検討、研修、研究、ソフトウェア開発です。災害時の運用指示を提供するものではなく、安全性や実在避難者の結果を予測・保証するものでもありません。

## 利用者とユースケース

- 避難所運営者や自治体担当者が、資源・人員・施設・サービスに関する明示的な仮定を比較する。
- 研究者や学生が、決定的な状態遷移やモデル差を調べる。
- 開発者が、イベント履歴、出典情報、Checkpoint、Branch差分を保ちながら機能を拡張する。

Scenarioは説明用の条件です。取込データ、仮定、承認時の注意事項を確認してから実行してください。実在する避難者の記録をfixtureやGitに登録してはいけません。

## 実装済み機能

- 人口、施設、期間、職員、物資、予定イベントを含むScenarioSpecの作成と検証。
- 安定IDとprovenanceを持つ合成人物の生成。上限付きの確認済み入力と修正。
- ニーズ、行動、施設queue、職員task、物資サービス、移動、運営イベント、および任意の社会・情報機構の実行。
- 型付きEffectProgramによる介入案の作成、全体検証、仮定のプレビュー、利用者承認、独立Branchへの適用。
- Checkpoint、過去時点のframe、Run復元、証拠検索、Branch比較。
- ローカルWeb画面、保存Run Inspector、CLI、永続Project store。
- 対応する準備、選択的なruntime提案、レビュー、保存済み証拠へのread-only質問のための、上限付き任意Claude連携。

利用できるoperator、入力schema、HTTP routeはAPIリファレンスとEffectProgram文書を参照してください。未対応機構は未対応のまま明示します。自然言語入力だけで新しいモデルを追加することはできません。

## 品質要件

- 対応する実行環境では、Scenario、seed、モデル版、Provider応答テープが同じなら、状態とイベント履歴も再現可能であること。
- 状態変更は型付きで検証可能、出典を追跡可能で、Branch間の変更を分離すること。
- Scenario、モデル、イベント、出典の版を永続データに記録すること。
- Inspectorとtraceの出力に上限を設け、read-only参照が状態を変更しないこと。
- offline利用と標準テストに外部アカウントや有料APIを必要としないこと。
- 利用者入力と取込計画を信頼せず、検証すること。

## 対象外と制約

- 避難者の行動、健康、安全、人員需要、介入効果の実世界予測。
- 診断、治療、服薬などの医療行為。
- 厳密な群集物理や衝突しない経路の保証。
- あらゆる施設図面やPDFの自動的・正確な意味解釈。
- 地域統計や予報が特定施設に適用できるという自動保証。
- 認証を備えたホスト型・マルチテナント運用。付属Webサーバーはローカル用途で、ユーザー認証を持ちません。

モデルの出典と仮定はmodel-validation.md、現行確認状況はtesting.md、出典・仮定台帳はfixtures/source-manifest.jsonを参照してください。
