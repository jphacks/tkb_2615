SHELTERSIM / PROJECT

条件を作り、避難所の時間と世界線を観察する

合成の人物とモデルによる試算です。実際の心理・健康・安全性を予測するものではありません。従来の固定デモ

Projectを読み込みます。

新しいシナリオを作成・編集

感情・情報の伝播は初期状態で無効です。有効化しても記録した接触・構造化イベントに限って伝播し、係数と応答は実測校正されていない実験仮定です。

身体・スタッフ・環境の実験モデル

式を切り替えると計算結果とCheckpointのモデル署名が変わります。係数は避難所の実測値で校正されていません。

Model Catalogに登録済みで、選択した式が実際に消費する係数だけを指定できます。単位・上下限、実在する避難者・職員・ゾーンID、許可されたサービス名・業務種別とゾーン別フィールドを検証し、設定と出典をScenario/Checkpointに保存します。個人別係数の未指定者は共有値を使います。スタッフ交代区間はstaff_dynamics v2で週内の[開始,end)分をスタッフID別に指定し、最大21区間・重複なしで入力できます。住民別の意思決定間隔は1〜1440分で指定でき、後から到着する人は共有間隔を使います。選択が効用softmaxの場合は住民別選択温度も指定できます。値は実験仮定で、実測校正を意味しません。

移動速度も移動区分別に上書きできます（例: movement_model.speed_m_per_minute_by_mobility.assisted）。単位はm/分で、値は移動時間計算とCheckpointに反映されます。

人口・世帯条件

医療以外の支援率は各合成人物に独立して適用する入力仮定です。許可される種別は caregiver_assistance、dependent_assistance、privacy_accommodation、mobility_assistance、hygiene_support、emotional_support、language_access です。dependent_assistanceは入力対象本人へ届く支援で、世帯関係からは自動推定しません。地域の実測割合や支援の効果を示す値ではありません。医療評価・服薬は上の別項目で指定します。

世帯テンプレートと明示する関係

年齢や同居から親子・介護・配偶者を推定しません。関係が分からない場合は未設定のままにできます。入力は匿名の合成世帯に使われ、未成年者や支援ニーズの確認ブロックを解除しません。ブロックされた個別Profileは確認できますが、人物IDを直接修正するAPIはありません。テンプレート・条件を修正して必ず再プレビューしてください。

世帯人数の重み（任意）

選択した世帯サイズの相対重みです。関係入力と一緒に使うには少なくとも1つの世帯テンプレートが必要です。空欄のサイズは分布へ追加しません。

高度な世帯構成 JSON

テンプレートはまだ追加されていません。未入力の関係は不明として扱います。

備蓄・設備・運営時間

設備の状態・数量

この入力はスタッフが対応できない時間を保存します。勤務可能時間は下の勤務予定JSONで別途指定します。役割・技能の割当てをこの欄で変更することはできません。時刻は開始からの分で、繰返しは24時間単位です。

スタッフの勤務可能時間

Scenarioプレビュー後に表示される合成スタッフIDを選び、Simulation開始からの週内1〜7日目と時刻を入力します。実際の曜日や日付とは同期しません。日をまたぐ勤務は翌週内の区間へ分割します。役割・技能は変更しません。不在・休憩予定は上の別入力で指定します。

勤務時間 JSON（上級者向け）

勤務時間を指定しない場合は、既存モデルの勤務規則を使います。

時刻はシミュレーション開始からの分です。設備IDやZone IDが存在しない場合はPreviewの阻害理由を確認してください。

対象日は地域資料/予報の検索条件です。シミュレーション日付や実際の避難開始時刻には同期しません。自治体名は候補一覧から明示選択できます。気象庁区域コードは利用者が資料で確認して指定します。細分区域/観測所の候補を選んでも、現在のAPIは自治体への適用確認や気象のScenario条件への結び付けを行いません（出典と未知状態を下で確認できます）。

詳細条件 JSON

上の入力欄にないモデル設定を確認・修正する場合に使用します。プレビュー後は編集すると承認が解除されます。

避難所図面の補正・取り込み

対応形式: PDF (1 asset 15 MiB以下、選択ページは0始まり・最大200ページ範囲)、PNG/JPEG/WebP (画像ページ0)、GeoJSON/JSON (ベクター候補)。PDFページ表示にはローカル同梱のPDF.jsを使い、PDF内容を外部へ送信しません。サーバーの任意依存 sheltersim[plan-import] (Pillow + pypdfium2) があれば抽出時の候補rasterも作ります。抽出は壁・開口の低信頼ヒューリスティックで、OCR、部屋名・設備・寸法の完全認識、縮尺推定はしません。rendererがない場合も表示中ページを背景に手動トレースできます。候補は未確定で、縮尺とGeometryは人が確認します。ベクターGeoJSON/JSONを使う場合は座標系がメートルであることを確認してください。確定Geometryは明示承認後に保存します。図面の権利・実在施設への適用性は運営者が確認してください。

ファイル未選択

ローカル同梱PDF.jsはPDFを表示し、選択ページ上の手動トレースに使えます。抽出は任意のサーバーPDFium/Pillow rendererを利用し、低信頼の壁・開口候補だけを返します。OCR・部屋名・設備・寸法の完全認識や縮尺推定は行いません。rendererがない場合は候補抽出が使えませんが、PDF.jsページ上の手動編集はできます。

選択ページ番号・raster参照・縮尺・候補・修正座標はProject草案に保存します。現在の確定Geometry APIには元PDFのページ番号フィールドがないため、最終Geometry単体ではPDFのどのページから作成したかを保持できません。

図面を選ぶか、標準図面を表示してください。手動確定した図形と抽出候補を分けて表示します。

Geometry検証結果はまだありません。

確定GeometryはimmutableなProject記録として保存されます。runtimeでの到達可能性検証は別途必要です。

最初のGeometryを保存した後、測量・運営者が記録した外部経路を追加し、新しいGeometry Revisionとして検証できます。既存Geometryは変更されません。

各経路の始点は全Zoneの外、終点は指定したdestination_zone_id内に置きます。全点はFacilityGeometryのメートル境界内で、source_kindとsource_idsには実際の根拠を記録してください。座標や入口までの距離は推測せず、検証後に新しいRevisionを明示承認してください。

標準施設のGeometryを補正・再検証

標準施設のプレビュー後、キャンバス上の点をドラッグして部屋・通路・設備の形状や位置を調整できます。壁・扉・開口・設備 footprint も選択して頂点を編集します。検証は新しいScenario候補を作り、元のScenario/Runは変更しません。容量不足・通行不能・幾何の不整合は承認前に具体的な指摘として表示します。

標準施設のプレビュー後に図面編集ができます。点をドラッグするとJSON草案に反映されます。

標準施設のgeometry / editable_geometry JSON（上級者向け）

外部到着の経路を設定する場合は geometry.arrival_approach_routes に、route_id・destination_zone_id・points_m・walking_speed_m_per_min・source_kind・source_ids を入力します。各点はこの図面のメートル座標範囲内に置き、始点を全Zoneの外、終点を指定Zone内にします。図面範囲の外やZoneへの入口までを実測できていない場合は値を推測せず、経路なしで実行してください。保存前にScenario全体を再検証し、到着介入でroute_idを明示選択します。

先に標準施設のScenarioをプレビューしてください。

複数の設備サービス点

各点はfacility ID、位置 (m)、アクセス条件、同時利用容量、queue IDを保存します。容量は1時間当たりの処理数ではありません。queue IDが既存runtime FIFOへ接続されない場合、待ち人数・サービス実績は不明のままです。追加・変更後は上のGeometry再検証を実行してください。

標準施設のPreview後にサービス点を編集できます。

入力・出典・仮定・不足条件をここに表示します。
